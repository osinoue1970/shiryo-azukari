# 資料 預かり・返却管理アプリ　導入手順書

このアプリを、**自分の事務所専用の環境**として使えるようにするための手順です。
パソコンでの作業に慣れた方なら、1〜2時間ほどで終わります。

- 預かり記録やお客様のサインは、**あなたの事務所のアカウント（Supabase）だけ**に保存されます。
- アプリの提供元を含め、ほかの事務所からは見えません。

---

## 準備するもの

| もの | 用途 | 費用の目安 |
| --- | --- | --- |
| メールアドレス | 各サービスへの登録 | — |
| GitHub アカウント | アプリのプログラムを受け取る | 無料 |
| Supabase アカウント | データの保存先（データベース） | 無料〜（下の「費用と注意点」を参照） |
| Vercel アカウント | アプリの公開先（URL） | 業務利用は有料プラン（下の「費用と注意点」を参照） |

## 手順1　Supabase でデータベースを作る

1. https://supabase.com にアクセスし、「Start your project」からアカウントを作ります（GitHubでのログインが簡単です）。
2. 「New project」を押し、次のように入力して「Create new project」を押します。
   - **Name**：わかりやすい名前（例：`azukari`）
   - **Database Password**：「Generate a password」で作り、**安全な場所に控えておく**（ふだんは使いません）
   - **Region**：**Northeast Asia (Tokyo)**
3. 数分待つと、プロジェクトの準備が終わります。

## 手順2　データベースの中身を作る（SQLを1回実行）

1. 左のメニューの「**SQL Editor**」を開きます。
2. 「New query」を押し、配布物の **`supabase/setup.sql` の中身をすべて**貼り付けます。
3. 右下の「**Run**」を押します。
4. 「Success. No rows returned」と出れば完了です。

> この作業は**最初の1回だけ**です。2回実行すると「すでにあります」というエラーになりますが、データは壊れません。

## 手順3　ログインの設定をする

1. 左のメニューの「**Authentication**」→「**Sign In / Providers**」を開きます。
2. 「**Confirm email**」（メールアドレスの確認）を**オフ**にして「Save」を押します。
   - このアプリは確認メールを使わず、**管理者が「利用を許可」する方式**です。
   - 近くにある「**Allow new users to sign up**」は**オンのまま**にしてください。

## 手順4　接続用の値を控える

1. 左下の「**Project Settings**」→「**API Keys**」（または「API」）を開きます。
2. 次の2つを控えます。
   - **Project URL**（`https://xxxx.supabase.co` の形）
   - **Publishable key**（`sb_publishable_` で始まるもの）

> ⚠️ 「secret」「service_role」と書かれた鍵は**絶対に使わない・人に渡さない**でください。

## 手順5　Vercel でアプリを公開する

1. https://vercel.com で、GitHub アカウントを使ってログインします。
2. 配布元のページ（https://github.com/osinoue1970/shiryo-azukari ）にある「**Deploy**」ボタンを押します。
   - 自分の GitHub にアプリのコピーが作られ、Vercel の設定画面が開きます。
3. リポジトリ名はそのままで構いません（非公開＝Private を選べる場合は Private を推奨）。
4. 「Environment Variables」に、手順4で控えた値を入れます。

   | 名前 | 値 |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Project URL |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key |

5. 「**Deploy**」を押します。1〜2分で完了し、`https://（名前）.vercel.app` のURLが発行されます。

> リンクを使わない場合：Vercel で「Add New → Project」から自分の GitHub にあるアプリのコピーを選び、**Root Directory を `app`** にして、上の2つの環境変数を設定してから Deploy します。

## 手順6　Supabase にアプリのURLを登録する

1. Supabase の「**Authentication**」→「**URL Configuration**」を開きます。
2. 「**Site URL**」に、手順5で発行されたURL（例：`https://azukari-xxxx.vercel.app`）を入れて保存します。
   - パスワード再設定メールのリンクはこのURLに戻ってきます。URLを変えたら、ここも直してください。

## 手順7　使い始める

1. **所長（管理者になる人）が最初に**、アプリのURLを開いて「はじめての方は職員登録」から登録します。
   - **最初に登録した人が自動的に管理者**になります。
2. 「**設定**」を開き、次を確認・変更して保存します。
   - **事務所名**（ラベルや預り証に印字されます）
   - **「長期」とみなす日数**（初期値 30日）
3. 職員に職員登録をしてもらい、管理者が「設定 → 職員」で「**利用を許可**」を押します。
4. 職員向けマニュアル（スライド）を配り、iPhone のホーム画面に追加してもらいます。
5. 職員は「設定 → 自分の情報」で**氏名**を入れてもらいます。氏名は担当者名として使われ、ホームと印刷待ちの「自分の分」の判定にも使います。

### 表示のしくみ（個人モードと管理者モード）

- ログインすると画面右上に自分の氏名が表示されます。タップすると設定・ログアウトができます。
- 一般の職員は、ホームと印刷待ちに**自分の担当分だけ**が初期表示されます（自分が預かった資料と、自分が返却した資料）。担当者の選択を「すべて」にすれば全員分も見られます。
- 管理者は右上の氏名から「**管理者モード**（全員の分を表示）」と「**個人モード**（自分の分だけ）」を切り替えられます。選んだモードはその端末で記憶されます。
- **他の人が預かった資料を返却するとき**は、ホームの検索欄で顧客名を探す（検索中は担当者に関係なく全員分から探します）か、資料に貼ったラベルのQRコードをiPhoneで読み取ります。返却した人が「返却担当者」として記録され、返却確認書はその人の印刷待ちに出ます。元の担当者の記録はそのまま残ります。

## 費用と注意点

- **Supabase（データ）**
  - 無料プランで動きます。ただし、無料プランは**1週間まったく使わないと一時停止**します（管理画面から再開できます）。また**自動バックアップがありません**。
  - お客様の大切な記録を守るため、**有料プラン（Pro：月25ドル程度）**をおすすめします。
  - 無料プランで使う場合は、ホーム画面の「CSV出力」で定期的に一覧を保存してください（サイン画像は含まれません）。
- **Vercel（公開）**
  - 無料の Hobby プランは**個人・非商用向け**です。事務所の業務で使う場合は、規約上 **Pro プラン（月20ドル程度）**が必要です。
- 料金や規約は各サービスの最新の案内を確認してください。

## PDFのメール送信（任意・上級者向け）

通常は不要です（PCの「印刷待ち」から印刷できます）。
PDFをメールで送りたい場合は、[Resend](https://resend.com) のAPIキーを取得し、Vercel の環境変数に `RESEND_API_KEY` と `MAIL_FROM`（送信元アドレス）を追加してください。
自分の事務所のドメインから送るには、Resend でドメインの認証（DNSの設定）が必要です。

## 困ったとき

**職員登録で「email rate limit exceeded」と出る**
手順3の「Confirm email」がオンのままです。オフにしてください。

**管理者が一人もいなくなった／管理者がログインできない**
Supabase の「SQL Editor」で、次を実行します（メールアドレスは管理者にしたい人のもの）。

```sql
set session_replication_role = replica;
update public.staff set active = true, is_admin = true where email = 'kanrisha@example.jp';
```

**パスワードを忘れた**
本人がログイン画面の「**パスワードを忘れた方**」からメールアドレスを入れると、再設定用のメールが届きます。メールのリンクを開くと新しいパスワードを設定できます（リンクの有効期限は1時間）。アカウントを削除する必要はありません。

- メールが届かないときは、迷惑メールを確認してください。Supabase の標準メールは送信数に上限があるため、短時間に何度も送ると「少し時間をおいて」と出ます。
- ログインできている人は「設定 → パスワード変更」で自分で変えられます。
- どうしてもメールが届かない場合は、管理者が Supabase の「SQL Editor」で仮パスワードを設定できます（仮パスワードは口頭で伝え、本人に「設定 → パスワード変更」で変えてもらってください）。

```sql
update auth.users set encrypted_password = crypt('仮パスワード', gen_salt('bf')) where email = 'honnin@example.jp';
```

## このアプリの仕組み（参考）

- サインした預かり内容と返却記録は、**データベース側で変更も削除もできない**ようにしてあります。
- すべての登録・変更は変更履歴（`audit_log`）に残ります。
- 預り証に印字される「照合コード」は、サインした時点の内容から計算した値です。
